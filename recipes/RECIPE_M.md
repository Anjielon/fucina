## 3. Deviations from the record (runner vs. original runs)

1. **No mount-namespace virtualisation** (the C runner has it). Steps 13-15 and 02-03 were verified bitwise without it. For step 05 see §9.
   If a writer embeds an absolute input path in the output, a step would show up as a hash mismatch, not pass silently.
2. **Step 11 is the original driver** `stato/apost_a_tappe_1101.sh` called with `PROVA=1 APOST_FINO=gguf APOST_TAPPE=50` (no run-register writes). It
   works only in the layout of the recording machine and needs the `tappe/*.pt` checkpoints (NAS copies; local `allena/*.nas` pointers).
3. **Wall-clock caps** (`--ore-max`) are part of the record for step 07 (stopped at step 200); the runner keeps the original value.
4. **Step 15 interpreter**: the original used the system `python3`; the runner uses the venv python (the system one lacks `tqdm` today). The output is identical.
5. **Step 03** compares JSON content, ignoring the `created` field.
6. Intermediate GGUFs are deleted after verification in anchored mode (`FORGIA_DISCARD_VERIFIED_GGUF=1`): `/mnt/models` has ~20-35 GiB free.

## 8. Gaps (honest list)

1. **Stage 0 is not re-run** (frozen root, hash-checked). Same as XS.
2. **Steps 01, 04, 07, 08, 10, 11 are GPU runs** that were not re-run for this document; step 10 took ~13 h of GPU. Bitwise identity is not claimed for the training steps.
   The launch has no GPU verification of them.
3. **The seed-1 dKL measurement (`dkl_completo`) has no archived launcher**; only the seed-2 launcher (`dkl_preciso/comando.sh`) exists. Both tables are recorded inputs.
4. **The PIENO incremental plan `piano_su_pv12p.json` was produced interactively**; no script that builds it from `piano_sek05.json` was found.
   It is a recorded input (hash `5ee8bd38…`); the writer step (05) is scripted.
5. **PIENO is `distortion_ok=false`** (max relative error 0.0209) and was accepted through `RD_TOLL_DIST=0.15`; the writer's own check is not clean.
6. **A-POST was restarted** after a machine restart; the 16 re-run steps resumed from the checkpoint (`--riprendi`), so the record is not a single uninterrupted run.
   The checkpoint intermediates (H1, npy dirs) were deleted; the `.pt` files of steps 50/100/150 are on the NAS with `.sha256` files.
7. **The MTP head was trained on Kaggle (2×T4) on C and grafted onto M**; the Kaggle launcher was not archived in the repository and the run cannot be repeated here.
   It is a recorded input verified per file.
8. **The unpacked splice file has no recorded hash**, and the manual creation of `Thor-T-M-packed-testaXS.gguf` on 6/11 was not logged
   **[inferred]**: splice on the unpacked T50, then pack. The inference is confirmed by the bitwise reproduction (§9).
9. **Selection of M by a rule that did not pass the registered gate**, and MMLU test-set use during development (§1).
10. **Two other packed M files exist** (head-less `69de7b53…` from the 3/11 release path, only on the Aragorn machine) and are not on the release path.
11. The Python environment of Oct/Nov was not frozen at the time (freeze copied from 22/10).
12. The per-question MMLU logs of the T50 and A readings (`mmlu_APOST50.log`, `mmlu_A_base.log`) are partial-run logs remapped to the shuffled bench
    (`parziale_mmlu.py --rimappa`); the scores come from `apost_tappe.tsv` / `mcnemar_vs_Abase.json`, hashed in `recorded/a_post_measurements.sha256`.

### 9.1 Step 16 executed on 12/11/2026 (GPU, launch engine `motore-lancio-1107`)
